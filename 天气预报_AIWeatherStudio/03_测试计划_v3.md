# H3 能力测试计划 v3（按用户 11-17 八条意见完善，等用户确认后才上卡）

## 这次要回答的五个问题（用户原话）

1. H3 的动作到底能控制到什么程度？
2. 固定的人物和服装，能不能跨镜头保持一致？
3. 录音驱动能不能解决口型同步？
4. 标准动作模板能不能长期复用？
5. 哪些问题必须靠后期合成解决？

## 一、几条原则

- **不预设失败。** 以前失败过的做法照样列为候选，用同一题目重测。每个能力至少比两条路，测出边界在哪。
- **一批一批来。** 每批跑完先给你看，你点头才开下一批。
- **每批交原始结果，不只交分数**，内容包括：
  - 原始视频（1080P 原件加手机版）；
  - 每条的参数：模型、工作流、种子、提示词全文、参考图 md5；
  - **实际**用时、进程显存峰值、整卡显存峰值；
  - 量数；
  - 失败的写清挂在哪、像是什么原因、下一步改哪一个变量。
- **跨镜头一致性是主要验收指标**，不只看单条片子。
- **动作模板按通用资源做**：天气、新闻、财经解说、其他人物视频都能用，不绑天气。
- **所有产物结构化保存**，以后能直接接进幕布平台出片（见第四节）。
- 固定做法照速查表原件，参数不改。H3 文字编码器一律用 8 位版。新做法先按作者原参数跑一遍，再改，一次只改一样。

### 第 4 批 P0-A：跨镜头一致性（最重要）

5 条镜头，同一人、同一套衣服、同一个演播室：
- 半身播报 5 秒
- 全身站立 5 秒
- 四分之三侧身看屏 5 秒
- 全身转身（正面 → 侧身 → 转回）5 秒
- 背面转回正面 5 秒

| 量什么 | 怎么量 | 成功标准 |
|---|---|---|
| 脸 | 每条每秒和 front_a 比人脸相似度，做 5×5 的跨镜头矩阵 | 正脸镜头达到「七七定版图之间的相似度」水平；侧脸另列，不和正脸同一条线 |
| 衣服 | 衣服各部位颜色和配件（领口蝴蝶结、珍珠、袜子蝴蝶结、短靴）逐条核对 | 5 条全在、颜色不跑 |
| 身体比例 | DWPose 量头身比、肩宽和头宽比 | 5 条之间差在 10% 以内（这个数是我定的初值，看完实测再调） |
| 观感 | 5 条按顺序剪在一起交你看 | 你看像同一个人 |

- 做法：PRISM 参考图直出（速查表 D 节，文戏的固定做法），1080P，1 个种子。
- **失败了怎么办**：
  - 脸漂：换成 fl2va 钉首帧（首帧用冻结的定妆图）再出一条对比；
  - 衣服丢件：参考图换成 T0-A 的三视图拼图；
  - 比例不对：喂对应景别的定妆图（姿势和景别跟参考图走，实测）。
- 估计用时：5 条 × 约 3.5 分钟 ≈ 18 分钟（1080P 单人 181–220 秒，实测）。

### 第 5 批 P0-B：动作控制边界（多条路一起比，不预设失败）

题目都一样：「从正面站 → 转向大屏 → 抬右手指向大屏某处 → 停住约 1.5 秒 → 放下 → 转回」，指上方、中间、下方三个目标。

| 路线 | 做法 | 状态 |
|---|---|---|
| R1 | fl2va 钉首帧（正面站）加尾帧（停住指向） | 速查表 B 节做法 |
| R2 | R1 再加一张中间钉帧（抬手到一半），用 AddGuide | 实测：衣服物理 4→7.5 |
| R3 | PRISM 参考图直出，参考图喂「指向」姿势图，提示词写动作 | 实测：姿势跟参考图走 |
| R4 | ControlNet 2.0 骨架控制，骨架从一段真人或 3D 指向动作里提 | 11-09 测过：第 2 帧会跳。这次照「骨架第 1 帧和首帧一致」的办法重测 |
| R5（对照） | viggle 换人，喂同一段驱动动作 | 它不是 H3 原生，只作参照 |

- R4、R5 需要一段「指向」驱动视频。我建议用 Mixamo 现成动作做灰模（攻击研究做过）或者找一段公开的指向动作视频，**要你定**。

| 量什么 | 成功标准 |
|---|---|
| 指尖停住段漂移（DWPose 肘 → 腕方向，取中位数和标准差） | 漂移不超过 10 像素（初值） |
| 抬手、放下自不自然（你看） | 不僵、没多手、手指正常 |
| 目标上、中、下三处能不能分开（落点差多少） | 三处落点明显分得开 |
| 同一条路换 3 个种子，落点差多少（P1 再做） | 差得小，模板就能预先算好坐标 |

- **失败了怎么办**：
  - 全部路线都指不准：退到「主播只做抬手和张开手掌介绍的大动作，指哪由地图高亮来表示」；
  - 某一条路好就收那一条。
- 估计用时：R1–R3 各 3 条，1376×768、1 个种子，每条约 2–2.5 分钟（124 帧 165 秒，实测，按帧数比例推）；R4、R5 各 1 条看趋势。合计约 30 分钟。R5 一段约 6 分钟，在 480p（实测）。

### 第 6 批 P0-C：口型和声音（T8 录音驱动为主）

同一句中文配音（T0-C 选定的那个声音），同一张半身定妆：

| 路线 | 做法 | 状态 |
|---|---|---|
| L1 主测 | T8「录音驱动」正式工作流，先照作者原参数（512×768、单段约 3 秒）跑，再试一档更高的分辨率 | 没测过；要下载一个权重（你已同意，下载前先报大小）；要起 8191 测试实例 |
| L2 | H3 原生节点的声音输入（AddGuide 的 audio 口），喂同一句配音 | 没测过 |
| L3 | H3 原声：同一句台词让 H3 自己说 | 实测过中文，会念错和自编 |
| L4 备用 | LatentSync 贴到 P0-A 的半身片上 | 实测，脸大时效果好 |
| L5 全身 | L1 和 L4 都在全身片上试一次，量脸宽，看嘴能不能对上 | 测出全身说话的边界 |

| 量什么 | 成功标准 |
|---|---|
| 嘴型和声音对不对得上 | 你看对得上，没有明显错位 |
| 身份 | 和 P0-A 同一个人（相似度矩阵加进来） |
| 动作 | 录音驱动之后身体动作自然、不僵 |
| 声音 | L1、L2 交付的是不是原样的我们那句配音（作者说「交付原录音」，核一下） |

- **失败了怎么办**：L1、L2 都不行，就走混合方案：半身用 LatentSync，全身做动作配画外音。
- 估计用时：L1 未知，作者没给耗时，我估连装模型约 5–10 分钟；L2、L3 各约 3.5 分钟；L4、L5 几分钟（LatentSync 没有耗时实测）。合计约 25 分钟（估）。

| 方案 | 做法 |

| 乙：固定地图 | 地图不动，挑落点离城市最近的那条指向模板。没有够近的，就记下「要为这个城市另出一条动作」 |

| 看什么 | 成功标准 |

## 四、产物怎么结构化保存（通用资源，不绑天气）

放在 `人物视频资源库\`（名字可改），四类，每类一个 JSON 加文件夹：

| 资源 | JSON 主要字段 | 例 |
|---|---|---|
| 人物 `presenter` | presenter_id、脸准绳图和 md5、定妆图（正、侧、背、半身、全身）、默认服装、默认声音 | `qiqi_anchor_01` |
| 服装 `outfit` | outfit_id、来源（服装库编号 AUT-0066）、改动（去包）、三视图和 md5 | `AUT-0066-nobag` |
| 动作模板 `motion` | motion_id、名称（指向上方等）、起始和结束姿势图、驱动来源（R1–R5 哪条）、时长、停住段时间、指尖坐标和漂移、适用景别、实测分 | `point_right_high_v1` |
| 声音 `voice` | voice_id、做法和种子、试听样本、你选定的日期 | `anchor_zh_01` |
| 每条跑的记录 `run` | run_id、用了哪几个资源 id、模型、工作流、参数、种子、提示词、实际用时、显存峰值、量数、失败原因、片子路径和 md5 | 一条片子一份 |

- 以后接进幕布平台：它已有角色、素材、出片版本这几张表，这几个 JSON 能直接导进去。
- 现在不改幕布平台的数据库结构。
